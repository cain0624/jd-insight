# 求职，我帮你 · 岗位知识库

让招聘信息可统计、可检索，并支持个人画像与简历决策。

**作品形态：可运行数据工具 / 模型按需配置**

[在线体验](https://cain0624.github.io/jd-insight/) · [个人作品集](https://kunyu-builds.s291623933.chatgpt.site/projects/jd-insight.html)

> 项目案例依据当前公开代码、页面、README 与提交记录整理。已实现、历史验证记录和下一步计划分别标明；模拟数据不作为真实业务结果。

## 背景

AI 产品岗位描述分散，求职者既想知道市场需求，也想判断个人经历和岗位的关系。原始 JD 列表难以直接支持这种比较。

作品把公开招聘信息组织成岗位知识库，连接统计问答、定性检索、个人画像和简历优化。



## 问题



- 数量与排名需要确定性统计，不能让模型凭印象给结论；定性问题又需要回到文本证据。
- 不同招聘来源的日期语义不同，混合发布时间与更新时间会产生误导趋势。
- 静态站没有 Python 后端，模型服务还有浏览器 CORS、Key 持久化和调用失败问题。

## 思考



- 把指标层交给 SQLite，把自然语言转 SQL 与定性分析交给模型，分清统计依据和文本依据。
- 保留日期语义与技能提及率口径，不将标签提及解释成岗位必备要求。
- 通过构建期适配和同构引擎复用前端，而非维护两套容易漂移的交互。

## 动作



- 把脱敏岗位知识库压缩分发，浏览器加载 SQLite，支持无需 Key 的指标类问答。
- 实现检索、画像、简历、会话与模型调用引擎，并提供用户自己的服务配置入口。
- 区分统计计算与需要模型的问题，在未配置或跨域失败时给出明确状态。

## 优化



- 提交记录显示：修复 Key 无法保存的静默问题，并增加构建期契约检查。
- 使用 gzip 版本降低知识库下载体积，并标注浏览器直连不可用的服务商条件。
- 下一步：固定版本评测统计口径与检索证据，记录 SQL 正确率、引用相关性及数据更新时间。

## 结果

已实现无需后端的岗位统计与知识库交互；指标问题可直接计算，模型功能需要配置可跨域访问的服务。

当前仓库是发布产物，原始来源已脱敏；没有公开求职成功率或简历优化收益验证。页面样本数会随知识库更新，不适合写成长期固定成果。

- 建议衡量：统计答案正确率、Text-to-SQL 执行与语义正确率、引用命中率、数据更新延迟、画像建议可解释性。
- 验收路径：提问一个指标问题 → 核对口径 → 配置模型后提定性问题 → 查看对应依据。

# 求职，我帮你

一个**纯静态**的 AI 产品经理岗位知识库：把公开招聘信息变成结构化数据，再在其上做
检索问答、画像匹配与简历优化。

线上地址：**https://cain0624.github.io/jd-insight/**

## 这个仓库是什么

它是**构建产物**，不是源码。目录结构：

```
index.html          单页应用（由 kb/web/index.html 在构建期注入而来）
engine/*.js         同构引擎：把本地版 Python 的逻辑逐字段移植到浏览器
assets/kb.sqlite    脱敏后的知识库（12.4MB，兜底用）
assets/kb.sqlite.gz 同一份库的 gzip（3.0MB，现代浏览器走这条）
vendor/sql-wasm.js  sql.js —— 在浏览器里跑 SQLite
ui/                 Key 设置面板与启动器
.nojekyll           关掉 GitHub Pages 的 Jekyll 处理
```

**不要直接改这里的文件。** 源在本地 `jd-insight` 项目里，改完用 `deploy.sh` 重新同步 ——
手改会在下次同步时被覆盖。

## 它怎么在没有后端的情况下工作

本地版有一个 Python 服务提供 `/api/*`。这个线上版没有服务端，但有同一套引擎：
页面在装载时把 `fetch` 接管，`/api/*` 的请求就地用浏览器里的引擎算出来，
数据从 `assets/kb.sqlite.gz` 解压到内存里的 SQLite。

所以：**`kb/web/index.html` 一行都不用改**，本地版与线上版共用同一份前端，
差异全部收敛在构建期。

## 关于 API Key

- **指标类问题不需要 Key**（如「各公司岗位数排行」「技能提及率 Top10」）——
  本地 SQL 直接算，打开就能问。
- **需要模型的问题**（自然语言转 SQL、定性检索、简历优化）要你自己填一个 Key：
  点右上角「设置」，填 Base URL / 模型名 / API Key。
- Key **只存在你自己浏览器的 localStorage 里**，不经过任何中间服务器，
  请求由浏览器直连你填的服务商。同一台机器上的其他脚本读得到它 —— 这一点在
  面板里写清楚了，没有假装它是安全的。
- 服务商**必须返回跨域头**（CORS）。这是纯静态站的硬门槛：带 `Authorization`
  的请求一定触发预检，服务端不回 `access-control-allow-origin` 就会被浏览器拦掉。
  实测`api.devin-tec.cn` 属于不回头的，所以面板里把它标成「浏览器直连不可用」——
  `curl` 能通不代表页面能用。

## 数据口径（避免误读）

- 样本来自公开招聘信息，城市已归一（「北京市」→「北京」），公司名**已脱敏**为别名。
- **日期语义按来源分开**：字节与飞书招聘是**首次发布**时间，腾讯/百度/网易是
  **最近更新时间**。两者不是一回事，所以不合并成一条曲线。
- 技能标签来自 JD 正文的关键词归一，是**提及率**而不是「岗位必备」。

## 更新流程（在本地源项目里）

```bash
.venv/bin/python tools/web_build.py     # 重建 publish/
./deploy.sh                             # 同步到本仓库并推送
```

`deploy.sh` 会先重建、再 `rsync --delete` 同步、然后提交推送。

## 许可与边界

仅用于公开信息的结构化分析。抓取遵循各站点 robots 与公开接口的访问约定；
仓库里不含任何原始 JD 全文，只有归一后的统计与脱敏摘录。
